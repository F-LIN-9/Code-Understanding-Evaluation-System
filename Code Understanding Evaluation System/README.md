# 面向 AI 辅助编程的代码理解测评系统

> 山东建筑大学大学生开放实验项目（学生参与科研型 · A 类）
> 项目名称：面向 AI 辅助编程的代码理解测评系统设计与实现
> 指导教师：李跃军　所在单位：计算机与人工智能学院　实验室：信息楼实验室

学生借助大模型可以很快写出"能跑"的代码，但程序能运行并不等于理解了它。
本系统以**学生本人提交的代码**为对象，自动生成代码解释、执行过程、错误诊断、
局部修改四类测评题，经**教师审核**后组织学生作答，再依据评分要点给出**分项反馈**，
为 AI 辅助编程环境下的学习过程评价提供工具支持。

---

## 一、功能概览

| 角色 | 功能 |
| --- | --- |
| 学生 | 提交代码（Python / Java / C / C++）、查看自己的提交、发起测评题生成、限时作答、查看分项报告 |
| 教师 | 审核候选题（通过 / 修改 / 删除）、发布或关闭测评、复核评分、查看班级与知识点统计、查看操作日志 |

完整业务闭环：

```
学生提交代码 → 代码结构预分析（AST/正则） → 生成候选题（大模型或内置规则引擎）
   → 教师逐题审核 → 发布测评 → 学生限时作答 → 客观题自动判分 + 开放题按评分要点初评
   → 教师复核确认 → 个人分项报告 / 班级知识点统计
```

设计要点：

1. **就着学生自己的代码提问**：题目绑定到具体行号与代码片段，减少"背题库"空间。
2. **教师审核前置**：大模型只产生候选题，未审核不能发布，审核记录可追溯。
3. **人机协同评价**：客观题精确判分，开放题按评分要点（关键词覆盖）初评或由大模型初评，
   教师保留最终判断权。
4. **可核验**：限时作答、报告留存、操作日志，便于配合现场改代码/答辩核验理解程度。
5. **可离线运行**：未配置大模型 API 时自动使用内置规则引擎，出题与评分仍可完整演示。

## 二、快速开始

环境要求：Windows / macOS / Linux，Python 3.9+，无需安装任何第三方包。


## 三、接入大模型

系统调用兼容 OpenAI 的 `/chat/completions` 接口。两种配置方式（任选其一）：

**方式一：环境变量**

```powershell
$env:CODEASSESS_LLM_BASE = "https://api.deepseek.com/v1"   # 或任意兼容网关
$env:CODEASSESS_LLM_KEY  = "sk-..."
$env:CODEASSESS_LLM_MODEL = "deepseek-chat"
python run.py
```

**方式二：`data/config.json`**

```json
{
  "base_url": "https://api.deepseek.com/v1",
  "model": "deepseek-chat",
  "api_key": "sk-...",
  "timeout": 60
}
```

未配置时系统处于**离线规则模式**（页面顶部会显示提示）：出题使用 AST/结构启发式规则，
评分使用评分要点关键词覆盖，功能与流程完全一致。

## 四、目录结构

```
代码理解测评系统/
├─ run.py            启动入口（建库 + 演示数据 + 启动服务）
├─ server.py         HTTP 服务、路由、业务接口、权限与审计
├─ db.py             SQLite 数据访问与表结构
├─ analyzer.py       代码结构分析（Python 用 ast，Java/C/C++ 用正则启发式）
├─ generator.py      出题：大模型优先，失败/离线时用规则引擎
├─ scoring.py        评分：选择题精确判分 + 开放题评分要点/大模型初评
├─ llm.py            OpenAI 兼容接口封装（无网络时安全降级）
├─ config.py         路径与大模型配置
├─ samples.py        15 个示例程序（也是案例集的素材）
├─ seed_demo.py      演示数据（代码、已发布测评、已评分作答）
├─ static/           前端页面（原生 HTML/CSS/JS，无构建步骤）
│  ├─ index.html  ├─ app.js  └─ styles.css
├─ tools/
│  ├─ smoke_test.py  端到端接口测试（覆盖全流程与权限校验）
│  └─ make_cases.py  生成《代码理解测评案例集》
└─ data/             运行时生成：codeassess.db、可选 config.json
```

## 五、数据表

| 表 | 说明 |
| --- | --- |
| `users` | 用户（教师/学生），演示环境无密码 |
| `codes` | 学生提交的代码（语言、课程、知识点） |
| `assessments` | 测评任务（状态：待审核 / 已发布 / 已关闭） |
| `questions` | 题目（类型、难度、选项、参考答案、评分要点、审核状态） |
| `attempts` | 作答记录（开始/提交时间、得分、状态） |
| `answers` | 逐题作答（原始作答、自动分、建议分、最终分、反馈、命中要点） |
| `audit` | 操作日志（登录、出题、审核、发布、交卷、复核） |

## 六、主要接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/login` | 登录（演示环境仅需账号） |
| GET | `/api/codes` | 代码列表（学生仅本人） |
| POST | `/api/codes` | 提交代码 |
| POST | `/api/codes/{id}/assessments` | 为该代码生成候选题 |
| GET | `/api/assessments` | 测评列表（含题目状态统计） |
| GET | `/api/assessments/{id}` | 测评详情（含题目与参考答案） |
| PATCH | `/api/questions/{id}` | 审核：`approve` / `reject` / `edit` |
| POST | `/api/assessments/{id}/publish` | 发布（要求无待审题目且有通过题目） |
| GET | `/api/student/assessments` | 学生可见测评及作答状态 |
| POST | `/api/assessments/{id}/attempts` | 开始作答 |
| POST | `/api/attempts/{id}/submit` | 交卷并自动评分 |
| POST | `/api/attempts/{id}/review` | 教师复核调整分数 |
| GET | `/api/report/{attemptId}` | 个人分项报告 |
| GET | `/api/stats/class` | 四类任务 / 知识点 / 学生得分统计 |
| GET | `/api/audit` | 操作日志（教师） |

接口统一返回 `{"ok": true, "data": ...}` 或 `{"ok": false, "error": "..."}`。

## 八、实现说明与后续工作

- **技术选型**：为便于离线演示与验收，原型用 Python 标准库实现（http.server + SQLite），
  前端为原生 JS。模块划分（提交、出题、审核、作答、评分、统计）与建议书中
  Spring Boot + Vue 方案一一对应，迁移时按层替换即可，业务规则与数据表结构可直接沿用。
- **出题质量**：规则引擎保证题目"必定与代码相关"（行号、函数名、循环次数均来自分析结果），
  但开放题的参考答案是按结构模板生成的，正式使用前必须经教师审核；接入大模型后题目表述
  会更自然，审核环节仍然是必需的质量关口。
- **评分**：当前开放题以评分要点关键词覆盖为主要依据，属于"可解释的初评"，适合形成
  分项反馈；更细的语义评判（如解释是否准确）留给教师复核与后续研究。
- **可扩展方向**：接入代码运行沙箱以自动生成"执行结果"类题目；支持班级/课程维度的权限；
  导出 Excel 成绩单；把审核记录与评分结果用于分析题目质量（正确率、区分度）。
